# batt 中文核心增强版

最近发布版本：`v0.8.0-zh.6`。基于 [charlie0129/batt](https://github.com/charlie0129/batt) 的 `2b9f8b579670b3d07365772f6f8e56b4f53912be`，沿用 GPL-2.0 许可证。

## 使用

- 系统首选语言为简体中文时显示中文，其余语言显示英文。更改系统或应用语言后，退出菜单栏应用并重新打开。
- “自定义充电范围…”同时设置停止充电上限和恢复充电下限。例如设置为 **75%–80%**：达到 80% 暂停，低于 75% 后恢复。输入须为整数，满足 `10 ≤ 下限 < 上限 ≤ 100`。
- 上下限作为一个事务保存；保存或应用失败时恢复此前的设置。正在校准时不能改动范围。明确设置新范围会取消临时停用计时和单次充电任务。
- 菜单栏图标固定为白色。将指针停在图标上即可阅读充电状态，包括正在充电、已达上限、区间保持或暂停原因未确认。退出菜单栏应用后，后台仍继续控制充电。
- “临时充满一次”沿用上游逻辑，不覆盖平时的范围；完成或取消后交回原限制。校准、主动放电、临时停用等高级功能保留。

## 启用已验证 M4 机型的 MagSafe 灯控

2026-11-01，用户以管理员权限（有效 UID 0）运行独立测试：橙灯 `4` 与绿灯 `3` 的写入、读回均匹配，恢复系统控制成功，并亲眼确认灯变绿。此前普通用户的权限错误不代表固件不支持灯控。

`v0.8.0-zh.2` 根据这次基础实测，开放以下精确组合的独立灯控：

| 项目 | 已测试值 |
|---|---|
| 机型 | Mac16,12（Apple M4） |
| macOS | 15.8.1 |
| 固件 | mBoot-20457.1.29 |

**开启路径：菜单栏 batt → 高级设置 → MagSafe 指示灯 → 启用（固件模式）。**

灯控默认关闭，需要手动启用。它继续使用原有固件限充，不切换成适配器断电模式，并保留已有充电范围。

从 `v0.8.0-zh.6` 起，接通电源后，仅在电量低于当前目标且电池正在充电时亮橙灯。电池未在充电，或电量达到或超过目标时，亮绿灯。例如设置 75%–80% 时，在 79% 重新插电且未充电，下一次有效采样会亮绿灯。选择“临时充满一次”后，当前目标为 100%。拔电、睡眠或采样无效时交回系统控制，正常更新间隔约 10 秒。

`v0.8.0-zh.3` 修复写入后过早校验造成的误停用：实测最初 0–11 毫秒仍返回旧灯色，约 50 毫秒时读回才匹配。后台现在只重复读取，分段等待总计最多 500 毫秒，匹配即结束；持续不匹配仍恢复系统，并在日志中记录期望值与实际读回值。真实写入或读取错误仍立即触发回退，不重复写入颜色。升级并重启后台会清除旧版会话的失败状态，已有启用偏好会保留。

`v0.8.0-zh.4` 支持失败后手动重新接管，无需重启后台：**高级设置 → MagSafe 指示灯 → 重新接管灯控**。失败时保留菜单，并清除表示正在接管的勾选。每次手动重试先写入系统控制；成功后解除失败锁定，在下一次状态采样时重新判断灯色，通常约10秒。恢复系统仍失败时保留失败状态、提示错误并回滚这次灯控设置。选择“禁用”或“常灭”也支持同样的恢复检查。菜单操作后立即刷新状态。

79% 重新插电时的灯色修复已经用户实机验证。写入或读回失败后会停止彩色控制，并尝试恢复系统；未能确认恢复时会明确提示。

机型、系统或固件与已测组合不符时，保留“尚未验证”状态和菜单栏回退。系统或固件升级后需要重新验证。配置识别只在后台启动时读取一次，不保留设备序列号或 UUID。

## 安装与升级

1. 保留一份原版 `batt.app`，然后退出旧菜单栏应用，后台服务继续运行。
2. 解压交付 ZIP，将新的 `batt.app` 放入“应用程序”文件夹，替换原应用。
3. 打开应用，首次安装选择“安装后台服务…”，升级时选择“升级后台服务…”，在系统弹窗中输入管理员密码。新版 GUI 需要配套后台才能使用新增功能。
4. 等待约 10 秒，核对显示的上下限与自己的设置一致，再按上述菜单路径启用灯控。已在该配置上启用的偏好会在后台重启后保留。

交付包使用本地 ad-hoc 签名，未作 Apple Developer ID 公证。

## 回退原版

先取消正在执行的单次充电和校准任务，退出新版菜单栏应用。用备份的原版覆盖“应用程序”中的 `batt.app`，重新打开并选择升级后台服务，以切换回原版后台。安装流程保留 `/etc/batt.json`；不要删除该文件。回退后核对上下限仍为你希望的范围。新版的单次充电任务不能交给旧版继续执行。

## 从源码构建

需要 macOS、Xcode Command Line Tools 和 Go 1.24.5 或兼容工具链。所有命令在源码根目录执行，当前含空格和中文的项目路径可直接构建。

```sh
go mod download
go test ./...
go test -race ./pkg/daemon ./pkg/client ./pkg/config ./pkg/compatibility ./pkg/powerinfo
go vet ./...
make app VERSION=v0.8.0-zh.6
codesign --force --deep --sign - bin/batt.app
```

产物为 `bin/batt.app`。Go 与 Objective-C 共用 `pkg/gui/locales/zh-Hans.json`，资源嵌入二进制，并随 app 附带副本。

只读硬件诊断：

```sh
go run ./hack/ledprobe
```

该诊断不改变指示灯或充电设置。自动测试全部使用模拟控制硬件，不会通过测试套件执行真实灯色写入。

## 接口

- 新增 `PUT /charge-range`，JSON 为 `{"upper":80,"lower":75}`；成功返回 201。后台拒绝无效范围、不支持的后端或校准冲突。保存与应用失败返回 500 并尝试恢复原设置。
- `/compatibility` 新增可选的 `chargeRange`、`magSafeLEDInterface` 和 `magSafeLEDReason` 和 `magSafeLEDRetry`。后者仅在已验证硬件的失败会话中为true，表示可手动恢复；它不表示当前灯控正在工作。`magSafeLED` 继续表示当前可用的自动灯控；接口存在与自动控制可用是两个概念。
- `/telemetry` 新增可选 `control`，包含目标、上下限、当前电量、状态原因、采样时间及灯控状态。`unknown` 或过期的采样不能作为达标依据。
- 旧 CLI、配置字段及接口继续保留。旧后台缺少新增能力时，GUI 会禁用范围编辑并提示升级。

此前版本的灯控修复见 [手动接管检查记录](docs/validation/2026-11-07-led-manual-retry.md)；此前修复见 [读回时序检查记录](docs/validation/2026-11-01-led-readback-timing.md)；固件能力验证见 [固件灯控检查记录](docs/validation/2026-11-01-firmware-led.md)；前版记录保存在 [首次交付检查](docs/validation/2026-11-01-zh-core.md)。
