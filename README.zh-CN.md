# batt 中文核心增强版

版本：`v0.8.0-zh.1`。基于 [charlie0129/batt](https://github.com/charlie0129/batt) 的 `2b9f8b579670b3d07365772f6f8e56b4f53912be`，沿用 GPL-2.0 许可证。

## 使用

- 系统首选语言为简体中文时显示中文，其余语言显示英文。更改系统或应用语言后，退出菜单栏应用并重新打开。
- “自定义充电范围…”同时设置停止充电上限和恢复充电下限。例如本次保留的 **75%–80%**：达到 80% 暂停，低于 75% 后恢复。输入须为整数，满足 `10 ≤ 下限 < 上限 ≤ 100`。
- 上下限作为一个事务保存；保存或应用失败时恢复此前的设置。正在校准时不能改动范围。明确设置新范围会取消临时停用计时和单次充电任务。
- 菜单栏图标绿色表示达到目标或有可靠依据的区间保持，橙色表示正在充电。“暂停·原因未确认”不会冒充“已达上限”。退出菜单栏应用后，后台仍继续控制充电。
- “临时充满一次”沿用上游逻辑，不覆盖平时的范围；完成或取消后交回原限制。校准、主动放电、临时停用等高级功能保留。

## 这台 M4 的 MagSafe 实测结果

在 macOS 15.8.1、固件控制充电的 M4 上，`ACLC` 指示灯接口可读取，读值为橙灯。但橙灯、绿灯以及系统控制写入均被 IOKit 拒绝，错误为 `0xe00002c1`。

因此本版在此控制模式下保留固件限充，使用**菜单栏状态回退**，不会为变更灯色切换成适配器断电模式，也不会强行开放实体灯控。读取到接口存在不等于拥有写入权限。当前版本未验证其他机型的实体灯行为。

在上游已支持自动灯控的控制模式下，后台统一串行写入灯色：充电、主动放电或校准为橙灯；确认达标或保持为绿灯；未知暂停、睡眠、拔插和读数失败交由系统控制。相同请求不重复写入；失败后禁用彩色控制，最多尝试三次恢复系统状态，恢复未成功会明确显示失败。

## 安装与升级

1. 保留一份原版 `batt.app`，然后退出旧菜单栏应用，后台服务继续运行。
2. 解压交付 ZIP，将新的 `batt.app` 放入“应用程序”文件夹，替换原应用。
3. 打开应用，选择“升级后台服务…”，在系统弹窗中输入管理员密码。新版 GUI 需要配套后台才能使用新增功能。
4. 检查显示的上下限。升级沿用已有配置；本次选择保留 **75%–80%**，不会重设成初次安装默认值。

本次交付阶段没有替换 `/Applications/batt.app` 或正在运行的后台，也没有改动现有充电配置。交付包使用本地 ad-hoc 签名，未作 Apple Developer ID 公证。

## 回退原版

先取消正在执行的单次充电和校准任务，退出新版菜单栏应用。用备份的原版覆盖“应用程序”中的 `batt.app`，重新打开并选择升级后台服务，以切换回原版后台。安装流程保留 `/etc/batt.json`；不要删除该文件。回退后核对上下限仍为你希望的范围。新版的单次充电任务不能交给旧版继续执行。

## 从源码构建

需要 macOS、Xcode Command Line Tools 和 Go 1.24.5 或兼容工具链。所有命令在源码根目录执行，当前含空格和中文的项目路径可直接构建。

```sh
go mod download
go test ./...
go test -race ./pkg/daemon ./pkg/client ./pkg/config ./pkg/compatibility ./pkg/powerinfo
go vet ./...
make app VERSION=v0.8.0-zh.1
codesign --force --deep --sign - bin/batt.app
```

产物为 `bin/batt.app`。Go 与 Objective-C 共用 `pkg/gui/locales/zh-Hans.json`，资源嵌入二进制，并随 app 附带副本。

只读硬件诊断：

```sh
go run ./hack/ledprobe
```

该诊断不改变指示灯或充电设置。自动测试全部使用模拟控制硬件，不会通过测试套件执行真实灯色写入。

## 接口

- 新增 `PUT /charge-range`，JSON 为 `{"upper":80,"lower":75}`；成功返回 201。后台拒绝无效范围、不支持的后端或校准冲突。保存与应用失败返回 500 并尝试恢复原设置。
- `/compatibility` 新增可选的 `chargeRange`、`magSafeLEDInterface` 和 `magSafeLEDReason`。`magSafeLED` 继续表示当前可用的自动灯控；接口存在与自动控制可用是两个概念。
- `/telemetry` 新增可选 `control`，包含目标、上下限、当前电量、状态原因、采样时间及灯控状态。`unknown` 或过期的采样不能作为达标依据。
- 旧 CLI、配置字段及接口继续保留。旧后台缺少新增能力时，GUI 会禁用范围编辑并提示升级。

详细验证见 [交付检查记录](docs/validation/2026-11-01-zh-core.md)。
