# v0.8.0-zh.4 灯控失败后的手动接管

## 缺陷与目标

用户报告：灯控失败后无法再次启用接管。2026-11-07只读检查已安装v0.8.0-zh.3，后台报告write_failed、desired=system、mode=enabled；充电状态仍为reached，当前/目标80%，下限75%。

两处原因：ledController.failed只在新进程启动时清除；GUI同时根据compatibility及telemetry.Available隐藏灯控菜单，使恢复入口消失。

用户希望失败后能显式重新启用。本版只在有效的手动设置请求中恢复；后台不会自动连续尝试彩色写入。

## 实现

- /compatibility新增可选magSafeLEDRetry。在底层已验证能力可用且会话失败时为true；magSafeLED继续为false，不混淆当前可用性和手动恢复能力。旧客户端可忽略新字段；新CLI允许使用恢复命令。
- GUI保留失败菜单，将启用项改为“重新接管灯控”，失败时清除接管勾选。telemetry中的失败状态不再覆盖compatibility对恢复入口的授权。旧后台未提供恢复能力时沿用原能力检查。
- PUT /magsafe-led在充电设置过渡锁中串行执行，仍检查底层能力与LED接口。严格接受enabled/disabled/always-off及原有布尔请求。无效请求不会保存、重置失败或写硬件。
- 保存有效设置成功后，失败会话先写入系统控制建立基线；只有该写入返回成功才清除失败与恢复尝试计数。先前三次自动系统恢复已耗尽的会话，也可以显式再次尝试。
- 建立基线仍失败时保留失败状态，回滚灯控偏好并返回错误；之后只进行原有的有限系统恢复尝试，不允许彩色写入。配置保存失败时不执行硬件恢复。
- 基线成功后更新LED遥测，保留充电目标达标记录。下一次正常采样根据插电、睡眠、电量、校准等当前条件判断颜色；通常约10秒。
- 硬件未验证或接口不可用时不提供恢复入口；没有放宽M4固件适配条件。充电后端、充电范围和高级任务不因灯控恢复而切换。

## 自动验证

回归用例先在v0.8.0-zh.3实现上确认失败：重复提交enabled不能解除失败、未提供恢复能力、系统恢复失败仍返回成功、保存失败不回滚内存偏好等。修复后通过。

测试使用临时配置和模拟SMC，覆盖已释放/恢复次数耗尽的失败会话、成功后重新写入绿灯、系统恢复失败及设置回滚、保存失败不写硬件、无效输入拒绝、布尔请求兼容、未验证设备拒绝，以及GUI恢复入口与中英双语标题。完整测试、竞态检查、静态检查、审查与安装包校验结果见BUILD-INFO.txt。

## 验证边界

开发阶段只读查看本机后台，未操作真实灯色、修改现有75%–80%配置或替换已安装服务。真实硬件上的手动恢复需用户安装配套GUI与后台后确认；系统写入成功表示命令返回成功，不能通过LED读回值0确认物理系统所有权。睡眠、拔插及长期稳定性仍需实机观察。
